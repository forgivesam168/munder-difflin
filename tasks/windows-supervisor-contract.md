   unused handles deterministically. Never open/kill a process found by name or PID scan.
4. Poll job accounting on a monotonic deadline (100ms candidate interval). Require
   successful ActiveProcesses==0 query and root exit status. Root exit alone does not
   stop supervision; a surviving child remains owned. Notifications may optimize later,
   but are not evidence substitutes. No new processes are assigned once launch finishes.
5. Candidate budgets: helper bootstrap 30s; run 40s; TerminateJobObject plus empty-job
   observation 10s. On run deadline, query failure or fixture failure, attempt termination
   once, persist outcome and query until cleanup deadline. Query failure is UNKNOWN,
   never zero. Close the job in finally even on receipt failure. No unbounded retry.
6. Outer Node deadline 85s includes margin; target only its retained helper process.
   Terminating the helper closes its sole job handle, a cleanup backstop, not observed
   empty-job evidence. Write incomplete/failure receipt, bound parent waiting and report
   unresolved cleanup. Missing heartbeat/final receipt never becomes PASS. Deadline
   bounds are application policy, not real-time guarantees under OS stalls.

## Receipt and acceptance

Persist source/binary/helper identities and stages before effects, then root exit,
termination attempted/result, last successful active count, query error numeric code,
deadline reason, observation time and final result. No environment values or raw errors.
Use same-directory temporary write and replace for each receipt snapshot; interrupted
or missing data is UNKNOWN, not success. Power-loss durability is not claimed.
The existing receipt helper must gain a separate verified-job-empty transition only
when integrated with real query evidence; do not add a free success override now.

PASS requires a structured fixture assertion result bound to this run/source identity,
root exit0, no timeout/error, and observed job empty. Exit0 or a loose log string alone
does not prove assertions ran. Receipt/termination exceptions must not bypass the
outermost finally that closes the job handle.
Forced termination may prove cleanup but still yields fixture FAIL. Helper death or
last-handle-close fallback yields cleanup UNVERIFIED unless separately observed by
the controlled test driver. Job empty means no associated active processes, not that
all host activity ceased or that filesystem/network/credential isolation exists.

## Windows verification matrix before Electron integration

Use only inert repository fixtures and synthetic env; all children are project-created.
Retain specific child handles or equivalent creation-bound evidence in the test driver;
do not rediscover by PID after exit. Test fixtures must have their own short finite
lifetime so a broken supervisor does not create an indefinite orphan during testing.

| Case | Required observable result |
| --- | --- |
| Root and child exit normally | Root exit0, job active count reaches0, receipt success. |
| Root exits while finite-lived child remains | Root exit does not finish monitor; child remains in job until exit/timeout. |
| Run deadline with child alive | Single termination attempt, observed zero if successful, fixture FAIL. |
| Kill helper while root/child alive | Retained handles signal exit under KILL_ON_JOB_CLOSE; production receipt remains incomplete. |
| Job setup/creation/assignment failure | No uncontained running child; error receipt, no fallback. |
| Query/terminate/receipt failure | Injected error stays failure/unknown; bounded wait, finally closes job. |
| Existing outer job/nested child job | Compatible nesting works, incompatible configuration fails closed. |
| Argument/env/handle boundaries | Exact argv, synthetic marker only, no inherited job handle or unintended stdio handles. |

First implementation checkpoint should implement helper and synthetic normal/root-early-
exit/deadline cases only after side-effect review. Then add crash/failure injection and
independent review before integrating Electron. Native Electron sandbox compatibility,
source identity binding, child path validation and file URL allowlist remain obligations.

## Limits, recovery and rollback

Not hostile-code isolation: broker/WMI-mediated creation and malicious same-user handle
manipulation are outside this fixture claim. Never generalize to company agents.
UNKNOWN: current host nesting/ABI/toolchain behavior, Electron sandbox child behavior.
No disabling Electron sandbox, breakaway allowance or broader host inspection to pass.
Keep outputs for diagnosis; rollback disables helper invocation and retains source gate
false. Do not delete unrelated files or kill unrelated processes to recover.
